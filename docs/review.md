# Review a story

Review the actual packet revision and its rendered pages. A schema pass checks
structure; it cannot certify a story's emotional effect, translation quality or
illustration accuracy. Use the project's required review kinds and record who
reviewed what, the revision and the findings.

| Pass | Questions |
| --- | --- |
| Editorial | Is the want clear? Does each attempt cause the next? Does the hero make the decisive choice? Is the ending earned? |
| Purpose | Do the named teaching goal and theme appear through action? Does the reader see the feeling before the fix? Is there an unnecessary lecture? |
| Continuity | Do cast, place, time, props, knowledge and relationships agree with the bible and earlier beats? Are new facts classified and referenced? |
| Read-aloud | Where does the reader stumble or run out of breath? Does repetition invite participation? Can a listener follow an action without explaining it? |
| Layout | Can the text be read at target size? Does the image add meaning? Are count, physical contact, framing, safe zones and page turns correct? |
| Art | Do the actual images match character references, scene actions, object support, prop counts and continuity across pages? |
| Translation | Does each edition preserve cause, tone, names and participation while sounding natural in its language? Has its layout been inspected? |

Use the [review worksheet](../templates/review.md) and
[read-aloud log](../templates/read-aloud.md). Record specific beat or page
references, the observed problem, the repair and its recheck. Distinguish blockers
from preferences; resolve the former and explain deliberate exceptions to the
latter.

Review statuses are `pending`, `passed`, `changes_requested` or `stale`. Record a
pass only for work actually reviewed at that revision. Proof records identify an
artifact path and whether that artifact has been reviewed. A file existing is
not a review, and a reviewed reading PDF does not establish print readiness.

The corresponding review kinds are `editorial`, `continuity`, `read_aloud`,
`layout`, `art` and `translation`. Purpose is part of the editorial review.

Changes invalidate evidence. Rebuild after source edits, or import a browser
bundle through the normal workflow, then recheck the affected work. Keep the
observations needed to understand a previous decision, but do not present stale
records as current approval. End the pass with an explicit result and any
remaining work; do not invent a reviewer's identity or claim a read-aloud test
that was only a silent text inspection.
