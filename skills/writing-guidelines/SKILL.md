# Set project guidelines

Read project settings, existing guidelines and the user's brief, then
[the craft guide](../../docs/guidelines.md). Separate binding requirements from
preferences; preserve intentional existing choices. Do not turn the picture-book
preset into a universal rule or silently change the requested format.

Write concrete rules in the existing guideline fields: what language sounds like,
what situations fit the audience, what teaching should achieve through action,
which boundaries apply, and how text and art share information. Choose a word
budget and review kinds suitable for the project. Record further distinctions in
`extensions` without replacing schema fields.

For every new rule, check whether a writer could make a decision from it. Remove
duplicate or conflicting instructions. Explain purposeful exceptions in project
notes. Rebuild and validate the workspace so changed context invalidates affected
evidence. Report the choices that changed and which existing stories need review;
do not claim that changing a rule has revised their manuscripts.
